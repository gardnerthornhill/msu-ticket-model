# MSU Ticket Model — public site design

Date: 2026-09-03. Direction chosen: **Editorial Big Board** (off-white ground, maroon accent,
condensed headlines, numbered game rows with a compact / deep-dive toggle).

## Audience

Mississippi State fans and boosters on a phone in game week, plus sports-business and analytics
readers on a desktop. They want: how full will Davis Wade be, how sure is the model, what drives
the number, and has it been right before. Trust comes from the track record and honest intervals.
The one action is reading this week's forecast and the reason behind it.

## What gets built

A fully static site, generated by the Python pipeline, served from `site/`.

| piece | purpose |
|---|---|
| `ticketmodel/site.py` | assembles one data dict from features, predictions, models and CFBD cache; renders Jinja templates into `site/` |
| `ticketmodel/logos.py` | downloads missing opponent logos from ESPN's CDN by CFBD team id into `logos/`; the MSU mark is `logos/msu.png` (transparent knock-out of `logos/MSU.png`) |
| `ticketmodel/templates/` | `base.html`, `index.html`, `track-record.html`, `game.html`, `model.html` |
| `ticketmodel/static/` | `site.css`, `site.js` (view toggle, season filter, table sort) |
| `site/` | generated output: HTML pages, `games/<season>-<slug>.html`, `logos/`, `data.json`, `robots.txt`, `sitemap.xml` |
| `python3 -m ticketmodel site` | new command; `all` runs it last, so the daily Action keeps the site current |

No build tooling: plain HTML, CSS and a small JS file. Local test: `python3 -m http.server -d site 8000`.
Hosting later: `.github/workflows/pages.yml` publishes `site/` with the GitHub Pages action.

## Pages

1. **2026 Outlook (`index.html`).** Hero is the next home game: opponent logo, date, forecast
   number, 80% band on the capacity track, sellout odds, get-in price. Below it the big board:
   every 2026 home game as a row, numbered by week. Toggle between compact rows and deep dive;
   deep dive shows the "why this number" breakdown inline.
2. **Track Record (`track-record.html`).** Headline accuracy (games, leave-one-out RMSE, share
   inside the 80% band). Scatter of forecast vs actual with a 45° line. Table of every 2023–2025
   game: price, forecast and band, actual, miss, inside band. Season filter chips, sortable.
3. **Game (`games/<season>-<slug>.html`).** Both logos, kickoff, forecast and band on the track,
   actual vs forecast when played, breakdown waterfall, the raw inputs, and any data notes
   (imputed Elo, last season's Elo).
4. **How It Works (`model.html`).** Plain-English pipeline, Tier 2 and Tier 1 weights with
   standard errors and a "seats of swing" bar (coefficient × typical range), leave-one-out
   accuracy table, feature selection, caveats, sources.

## Model performance and breakdowns

- Past games show the **leave-one-out** forecast (model fit without that game) and its 80%
  interval, so the track record is honest. `model.loo_intervals` is added for the interval.
- A game uses Tier 2 when it had a get-in price (and, for upcoming games, the season has three
  priced games), else Tier 1. The row says which.
- **Breakdown** centres each feature on its training mean: baseline = mean training attendance;
  each term's contribution = coefficient × (value − mean). Contributions sum to the forecast
  before clipping at capacity.
- **Sellout odds** = P(forecast + t·se ≥ capacity) from the same t interval.

## Visual system

- Colour: maroon `#5D1725` (primary), deep maroon `#3E0C17`, page `#F2F1EE`, surface `#FFFFFF`,
  ink `#1C1214`, secondary ink `#6B6266`, hairline `#DEDAD6`. Down-contributions use cool slate
  `#4E6E8E` as the diverging pole against maroon; status "inside band" uses green `#0C7A2B` with
  an icon and label, never colour alone.
- Type: Barlow Condensed (600–800) for headlines and big figures; Barlow (400–600) for body.
  Fallback: Arial Narrow / Helvetica / Arial.
- Layout: left-aligned, max 1120px, single column on phones. Rows separated by hairlines, not
  cards. One bold element per page: the forecast number beside its capacity track.
- Motion: only the deep-dive expand and the filter; respects reduced motion.

## SEO

Static HTML, one H1 per page, unique titles and descriptions, canonical URLs from a configurable
`SITE_URL`, `robots.txt` allowing AI crawlers, `sitemap.xml`, JSON-LD `WebSite` + `Dataset`.
Answer-first copy on every page; a genuine FAQ on How It Works.

## Testing

pytest covers `loo_intervals`, logo download with a fake http, the site data assembly (tiers,
breakdown sums, sellout odds, ids), rendering (files exist, logos referenced, no missing
templates), and the CLI `site` command. Visual check locally at desktop and phone widths.
